## 5. 測試方法：字形實際可見範圍（核准第 4 項；2026-11-04 依研究結果修正）

> 修正：前一版寫「用 `Paint.getTextBounds`」，跟研究文件 [§9.1](character-p7-7-prep.md) 已驗證的結果不一致（`getTextBounds` 有 `letterSpacing` 時會把字距留白算進字形，造成「英文月份被切 2%」「宜被切 1%」的誤報）。正式測試一律用**實際畫出來的像素**。

共用工具 `GlyphInk`（測試原始碼）：

| 檢查 | 量法 | 判定 |
|---|---|---|
| 字形被切 | 每一行用同一支 Paint 畫在透明圖上，取 alpha > 32 的像素外框（字形實際範圍），跟「自己 ∩ 每一層上層（clipToPadding 扣內距）∩ 外框」取交集 | 被切掉超過 1dp 就算截斷 |
| 省略與截斷 | `Layout.getEllipsisCount` 任何一行 > 0 | 一律算截斷（字形看得到也算） |
| 文字彼此碰撞 | 兩個 TextView 各自單獨畫出來（放回原座標）的有墨像素 | 有任何像素重疊就算碰撞 |
| 文字與墨丸 | 文字與墨丸 ImageView 各自的有墨像素（墨丸透明留白不算） | 有任何像素重疊就算碰撞；另外報最近距離 |
| 對比 | 字實際畫到的像素位置上，文字色對「拿掉這行字後」的背景 | 最差像素；門檻 4.5、設計目標 4.8 |

回歸測試（`GlyphInkTest`；每一項同時算舊量法，證明舊量法真的會錯）：

| 過去的問題 | 類型 | 測試 |
|---|---|---|
| 「截斷：天氣」、「英文月份被切 2%」 | 誤報 | 有字距的字串，外框切在實際字形右緣 + 0.5dp：舊量法（`getTextBounds`）判被切，新量法判完整 |
| T3／T4 日期被切一半卻判通過 | 漏報 | TextView 在外框裡但字形比 TextView 高：舊量法（TextView 邊界）判完整，新量法判被切 |
| 外框切字 | — | 上層比字窄：判被切 |
| 「…」 | — | 省略一律算截斷 |
| 方框重疊但字形沒碰到 | 誤報 | 兩行字的方框（行距留白）重疊、字形差 2px：舊量法判重疊，新量法判不碰；真的疊在一起要抓到 |
| 「忌×墨丸」（墨丸透明留白） | 誤報 | 圖片左半透明：字在透明處時新量法判不碰；伸進實心處要抓到 |

套用範圍：`WideLayoutTest`（截斷、對比）、`HomeShotsTest`（文字狀態）、導覽列與日曆頁的新測試。研究用的 `P77TallStructureTest` 也改成同樣的量法（碰撞從「有墨範圍的外框」改成像素，2026-11-04 最後一輪）。
